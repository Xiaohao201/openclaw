# “工作过程”时间线 — 前端渲染交接说明

后端通过 Mercure Hub 向每个用户的 topic 推送事件,驱动聊天气泡和折叠的“工作过程”面板。
本文档列出**前端需要消费的字段**。后端已经在发送这些数据;凡是标注「**前端待办**」的,
都是当前面板还没渲染、需要前端补上的部分。

事件统一通过 `POST {hubUrl}` 推送,`data` 为一个 JSON 对象。所有事件都带 `historyId`
(本轮对话的 id),前端可据此丢弃属于旧轮次的陈旧 SSE 消息。

> 来源:`extensions/rabbitmq-consumer/src/mercure-pusher.ts`(事件封装)、
> `src/tool-activity.ts`(`ActivityStep` 结构与脱敏)、`src/chat-pipeline.ts`(阶段步骤)。

---

## 1. 事件类型总览

| `type`                        | 含义                                             | 渲染位置         |
| ----------------------------- | ------------------------------------------------ | ---------------- |
| `text`                        | 回复正文增量(打字机)                             | 回复气泡         |
| `progress`                    | 脱敏的一句话进度(“正在查询分析数据（第 2 步）…”) | 临时“工作中”指示 |
| `step`                        | **结构化时间线步骤**(start/end)                  | 工作过程面板     |
| `done`                        | 本轮结束,停止动画                                | —                |
| `error`                       | 出错                                             | —                |
| `report_created` / `report_*` | 报告卡片占位与更新                               | 报告卡片         |

---

## 2. `step` 事件(工作过程面板的核心)

```jsonc
{
  "type": "step",
  "phase": "start" | "end",       // start 与 end 通过 stepId 配对
  "stepId": "tc-abc123",          // 同一步骤的 start/end 用同一个 id
  "index": 2,                      // 单调序号,用于排序
  "label": "正在分析舆情",          // 已脱敏的中文标签(可直接展示)
  "category": "query",             // 图标提示,见下表
  "status": "running" | "completed" | "failed",
  "durationMs": 3200,              // 仅 end 带:本步骤耗时(毫秒)
  "detail": "检测 3 项",            // 可选:已脱敏的一句话摘要(可能不存在)
  "historyId": 12345
}
```

### 配对与收尾规则

- 用 `stepId` 把 `start` 和 `end` 配对;`index` 决定显示顺序。
- 收到 `done` 时,**把所有仍为 `running` 的步骤就地标记为完成**(后端可能漏发某个 `end`,
  这是正常容错,不要因此卡住动画)。
- 同一 `stepId` 的阶段步骤(init/think/answer)只会 start/end 各一次,可放心去重。

### 合成阶段步骤(框定叙事)

除工具步骤外,后端还会发三个“阶段”步骤,让时间线读起来像一段叙事:

| `stepId` | `label`          | `category` | 何时出现                         |
| -------- | ---------------- | ---------- | -------------------------------- |
| `init`   | 正在理解您的问题 | `default`  | 每轮开头立即出现                 |
| `think`  | 正在思考分析     | `think`    | 模型流式输出推理时(并非每轮都有) |
| `answer` | 正在组织回答     | `answer`   | 首个回复增量出现时,直到本轮结束  |

## 3. 【前端待办】需要补充渲染的字段

后端**已经在发**以下数据,但当前面板尚未展示:

1. **`durationMs`(用时)** — 在每个已完成步骤旁显示耗时,例如 `✓ 正在分析舆情 · 3.2s`。
2. **`status`(状态)** — `completed` → ✓,`failed` → ✗/警示色,`running` → 转圈。
3. **`detail`(安全摘要,②)** — 若存在,作为标签的副标题/灰字补充,例如
   `正在发起侵权检测 · 检测 3 项`、`正在生成报告 · 周报`。`detail` 已做 CJK+数字 白名单
   脱敏,可**直接展示**,无需再处理;不存在时不显示。
4. **`detail` on `think`(思考摘要,③)** — `think` 步骤的 `end` 事件会带一段已脱敏、
   截断到 ~80 字的推理摘要。建议**默认折叠**,点击“思考过程”再展开。

### `category` → 图标建议

| category  | 含义               | category   | 含义          |
| --------- | ------------------ | ---------- | ------------- |
| `query`   | 数据查询/分析      | `check`    | 侵权/合规检测 |
| `read`    | 查阅资料           | `report`   | 报告/文书生成 |
| `write`   | 撰写/修改内容      | `think`    | 思考分析      |
| `search`  | 网络检索           | `answer`   | 组织回答      |
| `memory`  | 长期记忆/知识库    | `schedule` | 定时任务      |
| `default` | 通用步骤(兜底图标) |            |               |

> 遇到未知 `category` 一律回退到 `default` 图标 —— 后端将来可能新增类别。

---

## 4. ③ 思考摘要的隐私注意事项(给后端/产品)

`think` 步骤的 `detail` 暴露的是**模型原始推理**的截断片段。后端已做的防护:
`sanitizeInternalRefs` 去除工作区路径、注入的 `[userId:…]` 上下文、会话密钥;空白折叠;
硬截断到 80 字。但它**挡不住**内部数据表名、业务规则等。如需完全关闭,把
`chat-pipeline.ts` 中的 `REASONING_SUMMARY_ENABLED` 置为 `false`,届时 `think` 步骤
将只显示“正在思考分析”、不带 `detail`。
